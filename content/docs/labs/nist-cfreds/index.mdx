## What is CFReDS?

The **Computer Forensic Reference Data Sets (CFReDS)** project provides documented sets of simulated digital evidence for forensic examination, training, tool testing, and proficiency work.

This lab uses the public **NIST CFReDS Data Leakage Case**.

- [NIST CFReDS project](https://www.nist.gov/itl/csd/secure-systems-and-applications/computer-forensics-tool-testing-program-cftt/cfreds)
- [Data Leakage Case](https://cfreds-archive.nist.gov/data_leakage_case/data-leakage-case.html)

## The case story

The scenario follows **Iaman Informant**, a technology-development manager who is suspected of agreeing to leak sensitive company information to an employee of a rival company.

According to the scenario, the suspected leakage plan used ordinary-looking e-mail communication, personal cloud storage for sample data, and removable media for a larger transfer. A USB device and CD were detected at the company's security checkpoint and the devices were transferred for forensic examination.

The investigation objective is broader than finding a single file. We need to reconstruct the system, user activity, storage activity, network activity, and ultimately the evidence of data leakage.

## Evidence used in this learning path

The current learning path begins with the PC DD image:

~~~text
cfreds_2015_data_leakage_pc.dd
~~~

The image is approximately 20 GiB. NIST's dataset metadata describes the PC DD image as a DD-format image converted from the original virtual-disk source.

The lab treats the downloaded image as evidence to be independently examined. Dataset descriptions and answer material are reference material, not substitutes for deriving the result from the image.

## Investigation method

Each question follows the same evidence chain:

~~~text
Question
   ↓
Why the fact matters
   ↓
Evidence source
   ↓
How the artifact was located
   ↓
Tool-assisted examination
   ↓
Observed raw value or bytes
   ↓
Field structure / encoding
   ↓
Independent validation
   ↓
Answer
   ↓
What the evidence establishes
   ↓
What it does not establish
~~~

The goal is not to memorize a forensic tool's output. The goal is to understand where that output came from and how to verify it.
