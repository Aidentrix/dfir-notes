title: Q01 — Evidence Integrity and Hashing
description: Verify the PC evidence image before beginning forensic examination.
---

## Question

**What are the MD5 and SHA-1 values of the image, and do the verification values agree?**

The original NIST question covers all evidence images in the case. This learning path begins with the PC DD image:

~~~text
cfreds_2015_data_leakage_pc.dd
~~~

## Why this comes first

Before examining partitions, filesystems, Registry hives, user accounts, or timestamps, we first verify the evidence image itself.

The reason is simple:

~~~text
receive evidence
   ↓
calculate hashes
   ↓
compare with the expected / recorded hashes
   ↓
match?
   ├── yes → begin forensic examination
   └── no  → stop and investigate the discrepancy
~~~

There is little value in interpreting the contents of an image as the expected evidence set if its integrity has not first been established.

A hash does not tell us what happened on the computer. It tells us whether we are working with the same byte stream that was acquired or previously verified.

## Step 1 — Record the evidence object

Start by recording basic information about the file:

~~~bash
stat cfreds_2015_data_leakage_pc.dd
~~~

The image size observed in this lab was:

~~~text
21,474,836,480 bytes
20 GiB
~~~

This gives us a basic description of the object we are about to hash.

## Step 2 — Calculate the hashes

Calculate MD5 and SHA-1 directly from the complete image:

~~~bash
md5sum cfreds_2015_data_leakage_pc.dd
sha1sum cfreds_2015_data_leakage_pc.dd
~~~

Each command reads the full evidence image and produces a digest for that exact sequence of bytes.

## Step 3 — Compare the values

The calculated values were compared with the acquisition or verification hashes associated with the evidence set. Both values matched.

The decision point is:

~~~text
calculated MD5 / SHA-1
        ↓
compare with recorded values
        ↓
        match
        ↓
integrity verification passes
        ↓
proceed to Question 2
~~~

If a value does not match, the correct response is not to silently continue. The discrepancy should first be explained—for example, a different copy, a transfer problem, or a different version of the evidence image.

## Answer

The PC DD image is the evidence object used for the remainder of this learning path.

~~~text
MD5:         a49d1254c873808c58e6f1bcd60b5bde
SHA-1:       afe5c9ab487bd47a8a9856b1371c2384d44fd785

Verification: PASS
~~~

Both digests were calculated directly from the local `cfreds_2015_data_leakage_pc.dd` image and matched the recorded source/acquisition verification values.

## What this establishes

Hash verification establishes that the examined byte stream matches the byte stream represented by the recorded verification object.

## What this does not establish

A matching hash does not establish acquisition completeness, partition structure, filesystem type or contents, the installed operating system, users, activity, or attribution. Those conclusions require separate examination after integrity verification has passed.
