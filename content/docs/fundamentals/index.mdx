Fundamentals are the reusable ideas that make later artifact analysis understandable. The goal is not to memorize isolated magic values. The goal is to learn how an examiner moves from raw bytes to a defensible interpretation.

~~~text
evidence object
    ↓
locate the relevant bytes
    ↓
identify the documented structure
    ↓
decode the field using its defined representation
    ↓
interpret what the value means
    ↓
validate with an independent observation
    ↓
state the conclusion and its limits
~~~

A parser can accelerate this process, but parser output is still an interpretation of underlying evidence.

## How sources are used

These pages deliberately separate three kinds of material:

**Source basis** — documented concepts and structures. The primary source for disk, volume, and filesystem structure is Brian Carrier's *File System Forensic Analysis*. The source-reviewed Project Chronos BCS-00 and BCS-01 notes reinforce number systems, hexadecimal, sectors, LBA, and PC storage concepts.

**Worked evidence** — bytes and tool output actually observed in the NIST CFReDS Data Leakage PC image used in the lab.

**Validation** — a second representation, calculation, or tool used to check whether the interpretation agrees with the evidence.

The CFReDS lab is therefore an application of the fundamentals, not the source of the general rule.

## Evidence-first reading

Whenever a page shows raw evidence, read it in this order:

~~~text
where am I?
→ what bytes are present?
→ what structure applies here?
→ which bytes belong to the field?
→ how is that field encoded?
→ what value does it produce?
→ what other observation agrees with it?
~~~

That discipline is more important than memorizing any single offset.
