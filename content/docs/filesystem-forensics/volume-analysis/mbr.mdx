---
title: Master Boot Record (MBR)
description: Decode the canonical 512-byte MBR layout and its 16-byte partition entries.
---

The MBR used in this training material occupies the first logical sector of an MBR-partitioned disk. Its offsets are measured from the **beginning of disk / LBA 0**.

## Canonical 512-byte layout

| MBR-relative offset | Length | Field |
| --- | ---: | --- |
| `0x000-0x1BD` | 446 bytes | Bootstrap / MBR data area |
| `0x1BE-0x1CD` | 16 bytes | Partition entry 1 |
| `0x1CE-0x1DD` | 16 bytes | Partition entry 2 |
| `0x1DE-0x1ED` | 16 bytes | Partition entry 3 |
| `0x1EE-0x1FD` | 16 bytes | Partition entry 4 |
| `0x1FE-0x1FF` | 2 bytes | Signature; stored bytes `55 AA` |

Carrier presents the signature numerically as `0xAA55`. On disk the bytes are `55 AA`; interpreting those bytes as a little-endian 16-bit integer yields `0xAA55`.

The same signature pattern also appears in FAT and NTFS boot sectors, so it does not by itself prove a sector is an MBR.

## 16-byte partition entry

Offsets below are relative to the **beginning of the partition entry**.

| Entry-relative offset | Length | Field |
| --- | ---: | --- |
| `+0x00` | 1 byte | Boot/status |
| `+0x01` | 3 bytes | Starting CHS |
| `+0x04` | 1 byte | Partition type |
| `+0x05` | 3 bytes | Ending CHS |
| `+0x08` | 4 bytes | Starting LBA |
| `+0x0C` | 4 bytes | Sector count |

The starting-LBA and sector-count fields are little-endian multi-byte integers.

~~~text
starting LBA = address
sector count = quantity
final sector = start + count - 1
absolute byte offset = LBA × logical sector size
~~~

## CFReDS applied example

Observed disk values:

~~~text
Disk size:           20 GiB
Logical sector size: 512 bytes
Disk identifier:     0xf0265720
MBR signature bytes: 55 AA
~~~

Partition 1:

~~~text
active
type:                 0x07
start LBA:            2048
sector count:         204800
absolute byte offset: 0x100000
~~~

Partition 2:

~~~text
type:                 0x07
start LBA:            206848
sector count:         41734144
absolute byte offset: 0x6500000
~~~

Type `0x07` is not sufficient by itself to prove NTFS. [CFReDS Q02](/labs/nist-cfreds/q02-partition-layout) uses filesystem-level evidence from `fsstat` for confirmation and preserves the actual raw partition-entry bytes.
